# 给同学看的介绍

## 这到底是个什么项目

你可以把它理解成一个“翻译系统”。

我们现在遇到的问题不是宁德时代没有数据，而是：

- 宁德时代现在很多公开数据是 `公司级` 的
- 欧盟电池法想看的是 `某个电池型号 + 某个工厂`
- CBAM-compatible 的上游材料数据还想继续看到 `某个供应商 + 某种材料 + 某个上游工厂`

所以问题不在于“有没有数据”，而在于：

`现在的数据粒度不对。`

## 我们这个 demo 想证明什么

它想证明：

`同一套系统，可以同时服务欧盟电池法，还能顺手把上游材料的 CBAM 风格数据结构兼容进去。`

## 四层映射是什么意思

这四层不要想得太玄。

### 1. 字段映射

意思就是：

`CATL 现在手里这条数据，最后要填到欧盟或 CBAM 的哪个格子里？`

### 2. 证据映射

意思就是：

`你说这个数是真的，那你拿什么证明？`

比如：

- 电表
- 发票
- BOM
- 供应商 PCF
- 核验报告

### 3. 核验映射

意思就是：

`谁来确认这个数据能不能信？`

比如：

- 内部确认
- 第三方核验
- 供应商核验
- 公告机构/正式合规评估

### 4. 权限映射

意思就是：

`谁能看这个数据？`

不是所有数据都能公开。

有些可以公开给所有人看，有些只能给客户看，有些只能给监管或公告机构看。

## 为什么要单独做前端

因为表格虽然清楚，但表格更像研究和审查工具。

前端更适合：

- 给同学快速理解
- 给老师讲比赛方案
- 后续继续做成正式系统

## 为什么这个 demo 选神行 PLUS CTP

因为它比较复杂，也更贴近真实出海场景。

简单说：

- 它是动力电池
- 它是 pack 级，不是单个电芯
- 它已经和电池护照试点有比较强的公开锚点

所以先拿它做样板，后面换别的产品反而容易。

## 你看这个前端的时候，重点看什么

建议先看这 5 个地方：

1. 产品总览
2. 欧盟电池法输出
3. CBAM-compatible 输出
4. 四层映射逻辑
5. CATL 现有公开披露架构

## 一句话总结

这不是一个“从零编故事”的方案。

这是一个：

`把 CATL 已有能力继续拆细、继续结构化、继续变成 EU-ready / CBAM-compatible 输出的系统样板。`

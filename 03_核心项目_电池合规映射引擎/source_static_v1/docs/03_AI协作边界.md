# AI 协作边界

## 这份文档是给谁看的

这份文档主要是给后续接手开发的同学和 AI agent 看。

它的作用只有一个：

`告诉你哪些东西可以自由实现，哪些东西不能擅自改口径。`

## 这个项目里，什么是“已经基本定下来的”

下面这些内容，默认已经是当前 demo 的主线，不要随便推翻：

1. 这不是“重新发明标准”的项目，而是“把 CATL 现有数据继续拆细和重组”的项目。
2. 四层映射是主方法：
   - 字段映射
   - 证据映射
   - 核验映射
   - 权限映射
3. `Tractus-X` 不是自动转换器，它更像可信交换底座。
4. `CAB` 不是帮你算碳数据的人，它更像审核数据交换方案是否符合生态要求的人。
5. `CBAM-compatible` 这里的意思是：
   我们先兼容上游材料的 CBAM 风格字段和核验纪律，不要误说“整块电池已经直接纳入 CBAM”。
6. 当前 demo 最关键的难点不是“有没有数据”，而是“数据粒度不对”。

## 哪些事情可以交给后续 AI 或前端同学自由发挥

这些部分可以放心做：

- 页面布局和视觉优化
- 表格视图和卡片视图切换
- 角色切换按钮
- CSV / JSON 读取方式
- 前端状态管理
- 把静态数据换成文件驱动或 API 驱动
- 搜索、筛选、缺口高亮、证据链查看器

## 哪些事情不要擅自改

下面这些内容如果想改，先回到主模型重新确认：

- 欧盟电池法规和 CBAM 的定位关系
- 四层映射的方法论
- demo 产品和字段口径
- 哪些数据可以公开，哪些只能分层访问
- “公司级数据不能直接替代产品级合规数据”这个主判断
- 对 `Tractus-X`、`Catena-X`、`CAB` 的定义

## 最容易犯的三个错误

### 1. 把 Tractus-X 说成自动翻译器

不要这样讲。

更稳的说法是：

`Tractus-X 负责可信交换和互操作，不负责自动把原始数据变成欧盟合规答案。`

### 2. 把 CBAM 说成电池当前直接必过项目

不要这样讲。

更稳的说法是：

`这个 demo 兼容的是上游铝材、钢材等材料的 CBAM 风格数据结构。`

### 3. 把公司级 ESG 数据直接当成产品级合规数据

这正是本项目要解决的问题，不能反过来把它讲成已经解决了。

## 后续开发时的推荐分工

如果是“主模型 + 另一个 AI + 同学”一起做，建议这样分：

- 主模型：继续负责方法论、字段逻辑、合规口径、模型扩展
- 另一个 AI：负责前端页面、交互、样式、读取 CSV / JSON、简单数据联动
- 同学：负责审查字段、补数据、改展示语言、准备比赛表达

## 一句话提醒

这个仓库最重要的不是“做得多炫”，而是：

`让人一眼看懂每个字段从哪来、为什么能信、谁能看、最后要交到哪里。`

# 开发说明

## 当前技术选型

这一版故意用了最轻的方案：

- `HTML`
- `CSS`
- `原生 JavaScript`

原因很简单：

- 让任何人拿到仓库都能马上打开
- 不需要先装 Node、包管理器或框架
- 便于后续 AI agent 直接读文件和继续改

## 当前数据组织方式

当前前端数据主要来自：

- `frontend/data/demo-data.js`
- `data/review_csv/*.csv`

其中：

- `demo-data.js` 是前端直接渲染的主数据
- `review_csv` 是审查用的原始结构化底稿

## 为什么没有直接在前端里读取 CSV

主要有两个现实原因：

1. 直接双击打开本地 HTML 时，浏览器对 `fetch csv` 有时会受本地文件权限限制
2. 当前阶段最重要的是先把 demo 稳定展示出来

所以这一版选择：

`前端先吃一份整理好的 JS 数据对象`

后面再升级成：

- 读取 CSV
- 读取 JSON
- 读取后端 API

## 当前页面结构

前端现在建议保持单页结构，但分成几个视图：

1. `总览`
2. `EU 输出`
3. `CBAM 输出`
4. `四层映射`
5. `CATL 公开披露架构`
6. `开发提示`

## 后续最适合的升级路线

### 第一步：把静态数据改成文件驱动

优先级最高。

建议：

- 用 `review_csv` 生成 `JSON`
- 或直接从工作簿导出标准化 JSON

### 第二步：把手动输入和输出联动起来

现在这版更偏展示。

后续可以做成：

- 左边录入
- 右边自动更新 EU / CBAM 输出

### 第三步：加入角色视图

这是后续最有价值的一个升级点。

比如做四种查看模式：

- public
- customer / legitimate interest
- authority
- internal

### 第四步：再考虑迁移到 React / Vue

当前不急。

等下面三个条件满足时再迁移最划算：

- 页面数量明显增加
- 状态管理变复杂
- 数据开始来自 API

- `frontend/index.html`
- `frontend/styles.css`
- `frontend/app.js`
- `frontend/data/demo-data.js`
- `docs/00_给同学看的介绍.md`

## 开发时的核心原则

这套前端不要做成“花哨但空心”的展示页。

最重要的是：

- 让人一眼看懂逻辑
- 让人知道每个数据从哪来
- 让人知道哪些是现成可引用，哪些必须继续拆
- 让后续开发者能低成本接手

# 后续开发建议

## 如果你是继续开发这个 demo 的人

你最应该优先做的不是“换更高级的框架”，而是先把数据结构做稳。

## 建议优先级

### P1

- 把 `demo-data.js` 和 `review_csv` 做字段对齐
- 明确哪些字段是展示字段，哪些字段是底层计算字段
- 给每个字段补 `source`, `evidence`, `assurance`, `access` 标签

### P2

- 做一个“角色切换”开关
- 让同一条数据在不同角色下显示不同内容

### P3

- 做“产品切换”
- 现在只有一个 demo 产品
- 后面可以支持多个产品对比

### P4

- 接真正的工作簿或数据库
- 让前端不再依赖人工维护的 JS 数据

## 最容易做错的地方

### 1. 把 Tractus-X 当成自动转换器

不是。

它更像可信交换底座，不是“原始数据一丢进去自动变欧盟答案”的机器。

### 2. 把 CBAM 说成电池直接要过

现在不能这么讲。

更稳的说法是：

`我们兼容的是 CBAM 风格的上游材料数据结构。`

### 3. 把公司级 ESG 数据直接拿去当产品级合规数据

这正是我们要解决的问题。

必须继续往下拆粒度。

## 最推荐的下一版前端功能

- 表格视图和卡片视图切换
- 角色视图切换
- 缺口高亮
- “直接引用 / 需要拆分”筛选
- 证据链查看器
